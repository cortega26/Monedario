## D9 — mensaje de validación del simulador SuperIR (baja, abierto)

`src/pages/calculadoras/simulador-renegociacion.astro:643-646`:

```ts
if (deudas.some(deuda => deuda.acreedor.length === 0)) {
  showError(
    "Indica el acreedor de cada deuda: la ley exige dos o más obligaciones de acreedores distintos."
  );
```

El art. 260 verificado (S11) exige "obligaciones ... provenientes de
obligaciones diversas"; no exige "acreedores distintos". El motor corregido en
#589 (D3) tampoco exige acreedores distintos, y la nota de metodología de la
misma página ya dice "provenientes de obligaciones diversas"
(`simulador-renegociacion.astro:420`). El mensaje es el último resto del
criterio antiguo.

Cadena en el build limpio (worktree, dist de `pnpm run build`):

```
dist/_astro/simulador-renegociacion.astro_astro_type_script_index_0_lang.0GfvEoX7.js:
Indica el acreedor de cada deuda: la ley exige dos o más obligaciones de acreedores distintos.
```

También el JSDoc de `DebtItemInput.creditor` (SimulateDebtRenegotiation.ts:6-11)
sigue justificando el campo con "sin identificar al acreedor no es posible
verificar que sean distintas", criterio que el motor ya no aplica.
