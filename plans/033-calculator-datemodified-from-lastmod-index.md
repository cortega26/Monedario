## Why this matters

18 calculator pages emit `dateModified="2026-06-01"` as a hardcoded string literal
into their WebApplication JSON-LD. It is a frozen magic constant duplicated across
18 files that nobody updates, so the `dateModified` freshness signal on this YMYL
site silently ages and becomes misleading as the calculators change. The repo
already maintains the correct per-page date: `context/page-lastmod-index.json` is a
generated, git-derived `path → YYYY-MM-DD` map regenerated by
`scripts/build-page-lastmod.mjs` (CI workflow `page-lastmod.yml`), and
`astro.config.ts` already loads it for sitemap `lastmod`. This plan reuses that same
source so each calculator's `dateModified` is per-page, accurate, and
self-maintaining. The 4 calculators that intentionally surface a **data** date
(UF/UTM/IPC/IMM value freshness, not page-edit date) keep their current behavior.

## Steps

### Step 1: Add the `getPageLastmod` helper

Create `src/utils/pageLastmod.ts`:
```ts
import { readFileSync } from "node:fs";

type LastmodIndex = { pages?: Record<string, string> };

let cache: Record<string, string> | null = null;

function load(): Record<string, string> {
  if (cache) return cache;
  try {
    const raw = readFileSync("./context/page-lastmod-index.json", "utf-8");
    cache = (JSON.parse(raw) as LastmodIndex).pages ?? {};
  } catch {
    cache = {};
  }
  return cache;
}

/**
 * Fecha de última modificación (YYYY-MM-DD) de una ruta estática según el índice
 * generado `context/page-lastmod-index.json`. Normaliza la barra final.
 * Devuelve `undefined` si la ruta no está indexada (p. ej. una calculadora nueva
 * aún no incluida) — en ese caso no se emite `dateModified`, igual que hoy.
 */
export function getPageLastmod(pathname: string): string | undefined {
  const key = pathname.endsWith("/") ? pathname : `${pathname}/`;
  return load()[key];
}
```

**Verify**: `pnpm exec astro check` → 0 errors.
