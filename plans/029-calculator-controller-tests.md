## Why this matters

The coverage gate (`vitest.config.ts`, 80% lines) only measures
`src/application/**` and `src/domain/**`. The entire **client-side controller
layer** — the code that formats the pesos a reader actually sees and that
round-trips form values for saved scenarios — is invisible to it and has **zero
unit tests**. `src/pages/calculadoras/sueldo-liquido.astro` is the single most
churned source file in the repo (its controllers in `src/utils/sueldo-liquido/`
move with it), so a money-formatting or scenario-restore regression ships green
today. This plan adds the **test infrastructure** (a DOM environment for vitest)
plus characterization tests for the two highest-leverage, most-tractable targets:

1. `fmt` / `fmtPct` in `resultRenderer.ts` — the money/percent formatters used by
   **every** salary result line.
2. `snapshotInputs` / `restoreInputs` in `calculatorScenariosUI.ts` — the
   form-state round-trip **shared by 6 calculators**.

These are "characterization" tests: they pin *current* behavior so future
refactors (including the eventual CalculatorShell consolidation) have a safety
net. Deeply DOM-entangled orchestration (`formController.ts` full event flow,
`afpComparison.ts` rendering) is **explicitly deferred** — see Maintenance notes.

## Current state

`src/utils/sueldo-liquido/resultRenderer.ts:5–11` (pure, no DOM):

```ts
export function fmt(n: number): string {
  return "$" + Math.round(n).toLocaleString("es-CL");
}

export function fmtPct(n: number): string {
  return n.toFixed(2) + "%";
}
```

`src/utils/calculatorScenariosUI.ts:39–90` — `snapshotInputs(container)` reads
every `input`/`select` inside a container into a record (radios keyed `r:<name>`,
checkboxes `c:<id>` as `"1"`/`"0"`, everything else by element `id`);
`restoreInputs(container, data)` writes them back, dispatching `input`/`change`
events. Both require a real DOM (`document`, `HTMLInputElement`, `CSS.escape`).

**Test environment situation (important):**

- `vitest.config.ts` sets `environment: "node"`. There is **no** `happy-dom` or
  `jsdom` installed, and **no** existing test uses a DOM. So `fmt`/`fmtPct` can be
  tested as-is (pure), but `snapshotInputs`/`restoreInputs` need a DOM
  environment. Vitest supports a **per-file** environment via a docblock comment
  (`// @vitest-environment happy-dom`) without changing the global config — this
  plan uses that so the node default is preserved for all other tests.
- `happy-dom` is the lighter, standard choice and is already a recognized vitest
  peer (it appears under vitest's peer metadata in `pnpm-lock.yaml`).

**Conventions to follow:**

- Tests live under `tests/` mirroring the source area; import source via the `@`
  alias (configured in `vitest.config.ts`). Example existing unit test:
  `tests/unit/injectGlossaryLinks.test.ts`.
- The `@` alias maps to `src` — import as `@/utils/sueldo-liquido/resultRenderer`.

### Step 2: Characterization tests for the pure formatters (node env)

Create `tests/unit/calculator-controllers-format.test.ts`:

```ts
import { describe, expect, it } from "vitest";
import { fmt, fmtPct } from "@/utils/sueldo-liquido/resultRenderer";

describe("fmt (CLP formatter)", () => {
  it("formats whole pesos with es-CL thousands separators and a leading $", () => {
    expect(fmt(1200000)).toBe("$1.200.000");
  });
  it("rounds to the nearest peso (no decimals shown)", () => {
    expect(fmt(1200000.49)).toBe("$1.200.000");
    expect(fmt(1200000.5)).toBe("$1.200.001");
  });
  it("formats zero and small amounts", () => {
    expect(fmt(0)).toBe("$0");
    expect(fmt(999)).toBe("$999");
  });
  it("formats negative amounts (deltas/savings can be negative)", () => {
    expect(fmt(-4675827.73)).toBe("$-4.675.828");
  });
});

describe("fmtPct", () => {
  it("renders two decimals with a trailing %", () => {
    expect(fmtPct(1.27)).toBe("1.27%");
    expect(fmtPct(10)).toBe("10.00%");
  });
  it("rounds to two decimals", () => {
    expect(fmtPct(0.465)).toBe("0.47%");
  });
});
```

> Note: the expected `es-CL` grouping (`1.200.000`) is what Node's ICU produces;
> if your Node build's ICU yields a different separator the test will tell you —
> if so, STOP and report (do not weaken the assertion), because that would mean CI
> and local formatting diverge, which is itself a finding.

**Verify**: `pnpm test -- calculator-controllers-format` → all pass.

### Step 3: Characterization tests for the scenario round-trip (happy-dom env)

Create `tests/unit/calculator-controllers-scenario-io.test.ts`. The **first line**
must be the environment docblock:

```ts
// @vitest-environment happy-dom
import { afterEach, describe, expect, it } from "vitest";
import {
  snapshotInputs,
  restoreInputs,
} from "@/utils/calculatorScenariosUI";

function mount(html: string): HTMLElement {
  const container = document.createElement("div");
  container.innerHTML = html;
  document.body.appendChild(container);
  return container;
}

afterEach(() => {
  document.body.innerHTML = "";
});

describe("snapshotInputs", () => {
  it("captures text/number inputs and selects by id", () => {
    const c = mount(`
      <input id="sueldo" type="number" value="1200000" />
      <select id="afp-tasa"><option value="11.44" selected>Habitat</option></select>
    `);
    expect(snapshotInputs(c)).toEqual({ sueldo: "1200000", "afp-tasa": "11.44" });
  });

  it("keys the checked radio by r:<name> and ignores unchecked radios", () => {
    const c = mount(`
      <input type="radio" name="modo" value="bruto" checked />
      <input type="radio" name="modo" value="liquido" />
    `);
    expect(snapshotInputs(c)).toEqual({ "r:modo": "bruto" });
  });

  it("keys checkboxes by c:<id> as 1/0", () => {
    const c = mount(`
      <input type="checkbox" id="apv" checked />
      <input type="checkbox" id="extra" />
    `);
    expect(snapshotInputs(c)).toEqual({ "c:apv": "1", "c:extra": "0" });
  });
});

describe("restoreInputs round-trips with snapshotInputs", () => {
  it("writes values back so a re-snapshot equals the saved snapshot", () => {
    const c = mount(`
      <input id="sueldo" type="number" value="0" />
      <input type="radio" name="modo" value="bruto" />
      <input type="radio" name="modo" value="liquido" checked />
      <input type="checkbox" id="apv" />
      <select id="afp-tasa"><option value="11.44">Habitat</option><option value="11.45">PlanVital</option></select>
    `);
    const saved = {
      sueldo: "1500000",
      "r:modo": "bruto",
      "c:apv": "1",
      "afp-tasa": "11.45",
    };
    restoreInputs(c, saved);
    expect(snapshotInputs(c)).toEqual(saved);
  });

  it("dispatches input/change events when restoring a field", () => {
    const c = mount(`<input id="sueldo" type="number" value="0" />`);
    let inputs = 0;
    let changes = 0;
    c.querySelector("#sueldo")!.addEventListener("input", () => (inputs += 1));
    c.querySelector("#sueldo")!.addEventListener("change", () => (changes += 1));
    restoreInputs(c, { sueldo: "999" });
    expect(inputs).toBe(1);
    expect(changes).toBe(1);
  });
});
```

**Verify**: `pnpm test -- calculator-controllers-scenario-io` → all pass.
